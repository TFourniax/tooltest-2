## Storage and migration contract

An atomic hard-link publication cannot overwrite an existing observation. A
conflicting/corrupt record or failed write stops the state save; temporary files
are removed and staged records remain available for a retry. Successfully
published records may outlive a failed state write: they attest only captured
observations, never learning scores or current state. Directory symlinks and
nonregular/oversize files are rejected. Exact encoding and content hashes are
checked on every historical read. Power-loss durability across directory metadata
and hostile concurrent directory replacement are not newly guaranteed here.

Legacy migration seeds only retained valid observations on the next state save.
The normal state backup preserves the previous bytes. The historical discarded
counter is not reset; older missing observations are never reconstructed from
current source. A per-feature archive checkpoint avoids archive I/O on ordinary
state saves. Up to4MiB of pending records may be staged before an explicit save
is required; overflow fails instead of dropping an observation.

History is content-addressed, not an event chronology. Repeated identical states
are deduplicated, and earlier completeness remains unknown. Pages contain1..100
records in ID order; readers cap directory enumeration at100000 names and fail
explicitly above that boundary. Pages are not a frozen snapshot during concurrent
append. The existing3s/512KiB Core lineage boundary and32-link limit remain.
